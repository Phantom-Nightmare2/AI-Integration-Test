## Q01：厳密な整数解析と境界値

**難易度：上級**

### クライアント要望

外部システムから届く整数文字列を検証する処理です。入力文字列全体が正しい符号付き64ビット整数の場合だけ受理してください。部分一致・空文字・範囲外の数値は必ず拒否し、例外によって処理全体が停止しないよう修正してください。

### 元コード（編集禁止）

```cpp
#include <iostream>
#include <string>
#include <vector>

int main() {
    const std::vector<std::string> inputs = {
        "42", "-17", "9x", "9223372036854775807",
        "-9223372036854775808", "9223372036854775808", ""
    };
    for (const auto& s : inputs) {
        long long value = std::stoll(s);
        std::cout << "OK: " << value << '\n';
    }
}
```

### 期待結果・合格条件

順番に OK:42 / OK:-17 / INVALID:9x / OK:9223372036854775807 / OK:-9223372036854775808 / INVALID:9223372036854775808 / INVALID:(空文字) と判定する。表記方法は自由だが受理・拒否は一致させる。

### 必須要件

- 数値の一部だけを読み取って受理しない
- 符号付き64ビット整数の最大値と最小値を正しく扱う
- 不正入力を検出しても残りの検査を継続する
- 通常値、空文字、余分な文字、オーバーフローを検証する

### ★HERCULES回答欄 Q01

**【不具合の根本原因】**

1. **部分一致を受理する**：`std::stoll` は内部で `strtoll` と同じ規則を使います。先頭の空白を読み飛ばし、`+`／`-` 付きの数として読める**最長の先頭部分だけ**を変換します。元コードは第2引数 `pos`（消費した文字数）を受け取らず、文字列の末尾まで読んだかを確かめていません。そのため `"9x"` は 9 として受理されます。
2. **例外で処理全体が止まる**：数字が1つもない入力（空文字）では `std::invalid_argument`、64ビットの範囲外では `std::out_of_range` が投げられます。元コードには `try/catch` がないため、例外は `main` の外へ伝わって `std::terminate` から `abort()` が呼ばれます。範囲外の `"9223372036854775808"` の時点でプログラムが終了し、その後の空文字は検査されません。
3. 実測（MSVC）：元コードは終了コード `0xC0000409`（UCRT の `abort()`／`__fastfail`）で異常終了しました。標準出力はパイプ出力時にバッファされたまま破棄され、何も表示されませんでした。調査用プログラム（`try/catch` と `pos` で観測）の結果は次のとおりです。`"9x" -> 9 (consumed 1/2)`、`"9223372036854775808" -> std::out_of_range: stoll argument out of range`、`"" -> std::invalid_argument: invalid stoll argument`。

**【修正済みC++17コード：全文】**

```cpp
#include <charconv>
#include <cstdint>
#include <iostream>
#include <limits>
#include <optional>
#include <string>
#include <string_view>
#include <system_error>
#include <vector>

// 入力全体が10進の符号付き64ビット整数である場合だけ値を返す。
// 受理する書式: 省略可能な先頭の '-' と1桁以上の10進数字のみ。
// 拒否する書式: 空文字、先頭の '+'、前後の空白、余分な文字、範囲外の値。
// 例外は投げないので、不正な入力があっても呼び出し側は残りの検査を続けられる。
std::optional<std::int64_t> parseInt64Strict(std::string_view text) noexcept {
    if (text.empty()) {
        return std::nullopt;
    }
    std::int64_t value = 0;
    const char* const first = text.data();
    const char* const last = text.data() + text.size();
    const std::from_chars_result result = std::from_chars(first, last, value, 10);
    if (result.ec != std::errc{}) {
        return std::nullopt;  // invalid_argument（数字なし）または result_out_of_range
    }
    if (result.ptr != last) {
        return std::nullopt;  // 部分一致（"9x" など）
    }
    return value;
}

static std::string quoted(std::string_view s) {
    std::string out = "\"";
    for (char c : s) {
        if (c == '\0') {
            out += "\\0";
        } else {
            out += c;
        }
    }
    out += '"';
    return out;
}

static void report(std::string_view s) {
    if (const auto value = parseInt64Strict(s)) {
        std::cout << "OK: " << *value << '\n';
    } else {
        std::cout << "INVALID: " << quoted(s) << (s.empty() ? " (empty)" : "") << '\n';
    }
}

struct Case {
    std::string input;
    bool accept;
    std::int64_t expected;
};

int main() {
    static_assert(std::numeric_limits<std::int64_t>::max() == 9223372036854775807LL,
                  "int64_t must be 64-bit");

    // クライアント指定の入力（元コードと同じ順序）
    const std::vector<std::string> inputs = {
        "42", "-17", "9x", "9223372036854775807",
        "-9223372036854775808", "9223372036854775808", ""
    };
    for (const auto& s : inputs) {
        report(s);
    }

    // 追加検証: 通常値・境界値・空文字・余分な文字・オーバーフロー
    const std::int64_t kMax = std::numeric_limits<std::int64_t>::max();
    const std::int64_t kMin = std::numeric_limits<std::int64_t>::min();
    const std::vector<Case> cases = {
        {"42", true, 42},
        {"-17", true, -17},
        {"0", true, 0},
        {"-0", true, 0},
        {"007", true, 7},                         // 先頭ゼロは10進表記として受理
        {"9223372036854775807", true, kMax},      // 最大値
        {"-9223372036854775808", true, kMin},     // 最小値
        {"9223372036854775806", true, kMax - 1},
        {"-9223372036854775807", true, kMin + 1},
        {"9223372036854775808", false, 0},        // 最大値+1
        {"-9223372036854775809", false, 0},       // 最小値-1
        {"99999999999999999999999999", false, 0},
        {"", false, 0},
        {"9x", false, 0},
        {"x9", false, 0},
        {"1 ", false, 0},
        {" 1", false, 0},
        {"+1", false, 0},                         // '+' は拒否する方針
        {"-", false, 0},
        {"--1", false, 0},
        {"1-", false, 0},
        {"0x1A", false, 0},
        {"1e3", false, 0},
        {"1.0", false, 0},
        {std::string("12\0" "3", 4), false, 0},  // 途中にNUL文字
    };

    int passed = 0;
    int failed = 0;
    constexpr int kRepeat = 3;  // 同じ関数を繰り返し呼んでも結果が変わらないこと
    for (int round = 0; round < kRepeat; ++round) {
        for (const auto& c : cases) {
            const auto got = parseInt64Strict(c.input);
            const bool ok = c.accept ? (got.has_value() && *got == c.expected) : !got.has_value();
            if (ok) {
                ++passed;
            } else {
                ++failed;
                std::cout << "TEST FAIL: " << quoted(c.input) << '\n';
            }
        }
    }
    std::cout << "SelfTest: passed=" << passed << " failed=" << failed
              << " (cases=" << cases.size() << " x " << kRepeat << ")\n";
    return failed == 0 ? 0 : 1;
}
```

**【修正内容と安全性の説明】**

- `std::from_chars`（`<charconv>`）で `std::int64_t` に10進変換します。受理するのは `ec == std::errc{}`（変換成功かつ範囲内）で、しかも `ptr == last`（入力全体を消費）の場合だけです。部分一致（`"9x"`、`"1 "`、`"0x1A"`、`"1e3"`、途中に NUL を含む文字列）と範囲外（`errc::result_out_of_range`）はすべて拒否します。
- 空文字は先に明示して拒否します（`from_chars` でも `invalid_argument` になりますが、意図を明確にするため）。
- `from_chars` は例外を投げず、ロケールにも依存しません。関数は `noexcept` で `std::optional<std::int64_t>` を返します。不正な入力があってもループは止まらず、残りの入力を検査し続けます。
- 書式の方針：`from_chars` は先頭の `-` だけを受け付け、`+` と前後の空白は受け付けません。「入力全体が正しい整数」という要件に合わせ、`"+1"`、`" 1"`、`"1 "` は拒否します。`+` を許す必要があれば、先頭の `+` を1つだけ外して数字が続くことを確かめる処理を追加します。先頭ゼロ（`"007"`→7）と `"-0"`→0 は10進表記として受理します。
- `static_assert` で `int64_t` の最大値が 9223372036854775807 であることを確かめます。最大値・最小値はオーバーフローなしでそのまま表現できます（`from_chars` は最小値 `-9223372036854775808` を正しく変換します）。

## Q02：例外時にも状態を保つバッチ更新

**難易度：上級〜高難度**

### クライアント要望

在庫を一括更新します。途中で障害が発生した場合、在庫と監査ログの両方を処理前の状態に戻す『強い例外安全保証』を満たしてください。失敗後も、続く正常なバッチを実行できる必要があります。

### 元コード（編集禁止）

```cpp
#include <iostream>
#include <map>
#include <stdexcept>
#include <string>
#include <vector>

struct Change { std::string sku; int delta; };

class Inventory {
public:
    std::map<std::string, int> stock{{"A", 10}, {"B", 5}};
    std::vector<std::string> audit;

    void apply(const std::vector<Change>& changes, bool injectFailure) {
        for (std::size_t i = 0; i < changes.size(); ++i) {
            stock.at(changes[i].sku) += changes[i].delta;
            audit.push_back(changes[i].sku);
            if (injectFailure && i == 0) {
                throw std::runtime_error("simulated persistence failure");
            }
        }
    }
};

int main() {
    Inventory db;
    const std::vector<Change> batch{{"A", -3}, {"B", -2}};
    try {
        db.apply(batch, true);
    } catch (const std::exception& e) {
        std::cout << "Failure: " << e.what() << '\n';
    }
    std::cout << "After failure: A=" << db.stock.at("A")
              << " B=" << db.stock.at("B")
              << " Audit=" << db.audit.size() << '\n';
    db.apply(batch, false);
    std::cout << "After success: A=" << db.stock.at("A")
              << " B=" << db.stock.at("B")
              << " Audit=" << db.audit.size() << '\n';
}
```

### 期待結果・合格条件

障害発生後：A=10、B=5、Audit=0。続く正常実行後：A=7、B=3、Audit=2。さらに存在しない商品や在庫不足のバッチも全体を拒否し、状態を変更しない。

### 必須要件

- 在庫と監査ログをひとつのトランザクションとして扱う
- 例外が起きても一部だけ適用された状態を残さない
- 在庫が負になる変更と未知のSKUを拒否する
- 正常・障害注入・入力不正・再実行の4系統を検証する

### ★HERCULES回答欄 Q02

**【不具合の根本原因】**

1. `apply` はループの中で本体の `stock` と `audit` を直接書き換えています。1件目を適用して監査ログに追加した**後で**例外が出るため、`A` の減算と監査ログ1件が残ります。巻き戻しの仕組みはなく、強い例外安全保証どころか、在庫と監査ログの整合も業務上保てていません。
2. 実測（元コード）：`After failure: A=7 B=5 Audit=1`、`After success: A=4 B=3 Audit=3`。失敗したバッチの一部が残り、続く正常バッチがその上に重なっています。
3. 未知の SKU は `stock.at` が `std::out_of_range` を投げますが、それより前の要素はすでに適用済みなので、同じく一部だけが残ります。在庫が負になる変更も検査されていません。`int` の加算が桁あふれすると符号付きオーバーフローの未定義動作になる点も対策されていません。

**【修正済みC++17コード：全文】**

```cpp
#include <cstddef>
#include <iostream>
#include <limits>
#include <map>
#include <stdexcept>
#include <string>
#include <utility>
#include <vector>

struct Change { std::string sku; int delta; };

class Inventory {
public:
    std::map<std::string, int> stock{{"A", 10}, {"B", 5}};
    std::vector<std::string> audit;

    // 強い例外安全保証: 成功すれば在庫と監査ログの両方が更新され、
    // 例外が出た場合はどちらも呼び出し前の状態のまま残る。
    void apply(const std::vector<Change>& changes, bool injectFailure) {
        applyImpl(changes, injectFailure ? 0 : kNoFailure);
    }

    // テスト用: changes[failIndex] の処理直後に永続化障害を模擬する。
    void applyFailingAt(const std::vector<Change>& changes, std::size_t failIndex) {
        applyImpl(changes, failIndex);
    }

private:
    static constexpr std::size_t kNoFailure = static_cast<std::size_t>(-1);

    void applyImpl(const std::vector<Change>& changes, std::size_t failIndex) {
        // 1) 作業用コピーの上で検証と変更を行う（ここで何が投げられても本体は無変更）
        std::map<std::string, int> nextStock = stock;
        std::vector<std::string> nextAudit = audit;
        nextAudit.reserve(audit.size() + changes.size());

        for (std::size_t i = 0; i < changes.size(); ++i) {
            const Change& c = changes[i];
            const auto it = nextStock.find(c.sku);
            if (it == nextStock.end()) {
                throw std::invalid_argument("unknown SKU: " + c.sku);
            }
            const long long next = static_cast<long long>(it->second) + c.delta;
            if (next < 0) {
                throw std::invalid_argument("insufficient stock: " + c.sku);
            }
            if (next > std::numeric_limits<int>::max()) {
                throw std::overflow_error("stock overflow: " + c.sku);
            }
            it->second = static_cast<int>(next);  // 同一SKUが複数回あれば累積で検証される
            nextAudit.push_back(c.sku);
            if (i == failIndex) {
                throw std::runtime_error("simulated persistence failure");
            }
        }

        // 2) 確定: std::map / std::vector（標準アロケータ）の swap は noexcept
        static_assert(noexcept(stock.swap(nextStock)), "map::swap must be noexcept");
        static_assert(noexcept(audit.swap(nextAudit)), "vector::swap must be noexcept");
        stock.swap(nextStock);
        audit.swap(nextAudit);
    }
};

static int g_failures = 0;

static void check(bool cond, const std::string& label) {
    std::cout << (cond ? "  PASS: " : "  FAIL: ") << label << '\n';
    if (!cond) ++g_failures;
}

static bool stateIs(const Inventory& db, int a, int b, std::size_t auditSize) {
    return db.stock.size() == 2 && db.stock.at("A") == a && db.stock.at("B") == b &&
           db.audit.size() == auditSize;
}

// 例外が投げられ、状態が変わらないことを確認する
template <class Ex, class Fn>
static void expectRejected(Inventory& db, Fn fn, const std::string& label) {
    const auto stockBefore = db.stock;
    const auto auditBefore = db.audit;
    bool threwExpected = false;
    try {
        fn();
    } catch (const Ex& e) {
        threwExpected = true;
        std::cout << "  (rejected: " << e.what() << ")\n";
    }
    check(threwExpected && db.stock == stockBefore && db.audit == auditBefore,
          label + " -> rejected, state unchanged");
}

int main() {
    // 元のシナリオ
    Inventory db;
    const std::vector<Change> batch{{"A", -3}, {"B", -2}};
    try {
        db.apply(batch, true);
    } catch (const std::exception& e) {
        std::cout << "Failure: " << e.what() << '\n';
    }
    std::cout << "After failure: A=" << db.stock.at("A")
              << " B=" << db.stock.at("B")
              << " Audit=" << db.audit.size() << '\n';
    db.apply(batch, false);
    std::cout << "After success: A=" << db.stock.at("A")
              << " B=" << db.stock.at("B")
              << " Audit=" << db.audit.size() << '\n';

    std::cout << "[Tests]\n";
    check(stateIs(db, 7, 3, 2), "normal batch after injected failure: A=7 B=3 Audit=2");

    // 障害注入: 先頭・末尾の両方
    expectRejected<std::runtime_error>(db, [&] { db.applyFailingAt(batch, 0); },
                                       "failure injected at index 0");
    expectRejected<std::runtime_error>(db, [&] { db.applyFailingAt(batch, 1); },
                                       "failure injected at last index");

    // 入力不正: 未知SKU（既知SKUの変更の後に出現しても全体を拒否）
    expectRejected<std::invalid_argument>(db, [&] { db.apply({{"A", -1}, {"Z", 1}}, false); },
                                          "unknown SKU after valid change");
    // 入力不正: 在庫不足（B=3 に対して -4）
    expectRejected<std::invalid_argument>(db, [&] { db.apply({{"A", -1}, {"B", -4}}, false); },
                                          "insufficient stock (B=3, delta -4)");
    // 入力不正: 同一SKUの累積で負になる（A=7: -4, -4）
    expectRejected<std::invalid_argument>(db, [&] { db.apply({{"A", -4}, {"A", -4}}, false); },
                                          "cumulative duplicate SKU goes negative");
    // 入力不正: int のオーバーフロー
    expectRejected<std::overflow_error>(
        db, [&] { db.apply({{"A", std::numeric_limits<int>::max()}}, false); },
        "stock overflow (A + INT_MAX)");

    check(stateIs(db, 7, 3, 2), "state after all rejected batches: A=7 B=3 Audit=2");

    // 空バッチは何も変えない
    db.apply({}, false);
    check(stateIs(db, 7, 3, 2), "empty batch keeps state");

    // 再実行: 失敗の後でも正常バッチが続けて適用できる
    db.apply(batch, false);
    check(stateIs(db, 4, 1, 4), "re-run normal batch: A=4 B=1 Audit=4");

    // 境界値: ちょうど0までは許可
    db.apply({{"A", -4}, {"B", -1}}, false);
    check(stateIs(db, 0, 0, 6), "draining to exactly 0 is allowed: A=0 B=0 Audit=6");
    expectRejected<std::invalid_argument>(db, [&] { db.apply({{"A", -1}}, false); },
                                          "below zero from 0");

    std::cout << "Result: " << (g_failures == 0 ? "ALL PASS" : "FAILURES") << " (failures="
              << g_failures << ")\n";
    return g_failures == 0 ? 0 : 1;
}
```

**【修正内容と安全性の説明】**

- **copy-and-swap によるトランザクション**：`stock` と `audit` の作業用コピーを作り、検証と変更はすべてコピーの上で行います。コピーの作成、`find`、`push_back`、障害注入のどこで例外が出ても、本体は一切変更されていません。最後に `std::map::swap` と `std::vector::swap` で確定します。標準アロケータでのこの2つは `noexcept` で、`static_assert(noexcept(...))` でも確かめています。確定の段階で失敗することはなく、在庫と監査ログは必ず一緒に更新されます。

## Q04：オブジェクトスライシングと多態性

**難易度：上級**

### クライアント要望

図形の面積を一覧表示するC++プログラムです。派生クラスの値を基底クラスとして格納したため、正しい面積が表示されません。所有権と破棄時の安全性も考慮し、多態性を保持する設計に修正してください。

### 元コード（編集禁止）

```cpp
#include <iostream>
#include <vector>

struct Shape {
    virtual int area() const { return -1; }
    ~Shape() = default;
};

struct Rectangle : Shape {
    int w;
    int h;
    Rectangle(int width, int height) : w(width), h(height) {}
    int area() const override { return w * h; }
};

int main() {
    std::vector<Shape> shapes;
    shapes.push_back(Rectangle(3, 4));
    shapes.push_back(Rectangle(5, 6));
    for (const Shape& shape : shapes) {
        std::cout << "Area: " << shape.area() << '\n';
    }
}
```

### 期待結果・合格条件

Area: 12 および Area: 30 の2行を順に表示する。基底クラス経由で保持・破棄しても型固有の処理が失われない。

### 必須要件

- スライシングが発生する原因を説明する
- 図形オブジェクトの安全な所有方法を採用する
- 基底クラスを通じた破棄でも未定義動作を起こさない
- 少なくとも2種類の図形で拡張可能性を検証する

### ★HERCULES回答欄 Q04

**【不具合の根本原因】**

1. **スライシング**：`std::vector<Shape>` は `Shape` 型のオブジェクトを値として格納します。`push_back(Rectangle(3, 4))` では `Shape` の暗黙のコピーコンストラクタが呼ばれ、`Rectangle` の中の `Shape` 部分だけが複製されます。`w`・`h` は捨てられ、格納された要素の動的型は `Shape` です（vptr は `Shape` のもの）。そのため `shape.area()` は仮想関数でも `Shape::area()` を呼び、`-1` を返します。
2. 実測（元コード）：`Area: -1` が2回表示されました（未定義動作ではなく、規格どおりの誤動作）。
3. **基底クラスのデストラクタが非仮想**：`~Shape()` が `virtual` ではありません。多態性を保つために `Shape*`／`std::unique_ptr<Shape>` で派生オブジェクトを持つよう直しても、基底クラスへのポインタ経由で `delete` すると未定義動作になります（派生クラスのデストラクタが呼ばれない）。スライシングだけ直してもこの問題が残ります。

**【修正済みC++17コード：全文】**

```cpp
#include <climits>
#include <iostream>
#include <memory>
#include <stdexcept>
#include <string>
#include <type_traits>
#include <vector>

// 抽象基底クラス。値として保持できない（抽象）、コピーもできない（スライシング防止）。
struct Shape {
    Shape() { ++alive; }
    Shape(const Shape&) = delete;
    Shape& operator=(const Shape&) = delete;
    virtual ~Shape() { --alive; }  // 基底クラス経由の delete で派生のデストラクタも呼ばれる

    virtual int area() const = 0;
    virtual std::string name() const = 0;

    static inline int alive = 0;  // 生存中の図形の数（破棄検証用）
};

struct Rectangle : Shape {
    int w;
    int h;
    Rectangle(int width, int height) : w(width), h(height) {
        if (width < 0 || height < 0) {
            throw std::invalid_argument("negative size");
        }
        if (height != 0 && width > INT_MAX / height) {
            throw std::overflow_error("area overflows int");  // 符号付きオーバーフロー(UB)を防ぐ
        }
    }
    ~Rectangle() override { ++destroyed; }
    int area() const override { return w * h; }
    std::string name() const override { return "Rectangle"; }

    static inline int destroyed = 0;
};

struct Square final : Rectangle {
    explicit Square(int side) : Rectangle(side, side) {}
    std::string name() const override { return "Square"; }
};

struct RightTriangle final : Shape {
    int base;
    int height;
    RightTriangle(int b, int h) : base(b), height(h) {
        if (b < 0 || h < 0) {
            throw std::invalid_argument("negative size");
        }
```

## Q05：unordered_mapの反復中の再ハッシュ

**難易度：上級〜高難度**

### クライアント要望

集計表に元データを残したまま copy- を付けた複製データを追加してください。元データをたどりながら同じ連想コンテナに挿入する現状は、再ハッシュや反復対象の増加により動作が保証されません。

### 元コード（編集禁止）

```cpp
#include <iostream>
#include <string>
#include <unordered_map>

int main() {
    std::unordered_map<std::string, int> counts{
        {"A", 2}, {"B", 3}, {"C", 5}
    };
    for (auto it = counts.begin(); it != counts.end(); ++it) {
        counts["copy-" + it->first] = it->second;
    }
    for (const auto& item : counts) {
        std::cout << item.first << '=' << item.second << '\n';
    }
}
```

### 期待結果・合格条件

キーと値は A=2、B=3、C=5、copy-A=2、copy-B=3、copy-C=5 の6件だけ。表示順はキーの昇順とし、copy-copy- から始まるキーを生成しない。

### 必須要件

- 挿入時のイテレータ無効化と反復対象増加の危険を説明する
- 元の3件だけを複製する
- 再ハッシュが起きても安全に動く
- 空の入力と大量件数でも動作を確認する

### ★HERCULES回答欄 Q05

**【不具合の根本原因】**

1. **反復中の挿入**：`counts` をイテレータでたどりながら、同じ `counts` に `operator[]` で要素を挿入しています。規格では、挿入で再ハッシュが起きると**すべてのイテレータが無効**になります。再ハッシュの後で `++it` を実行するのは未定義動作です。
2. **反復対象の増加**：再ハッシュが起きなくても、新しい要素がまだ訪れていない位置に入れば、その要素も反復で訪れます。`copy-A` を訪れると `copy-copy-A` が作られ、連鎖します。反復の終わりは要素の配置次第で、決まりません。
3. 表示順：`std::unordered_map` の反復順は規定されておらず、「キーの昇順」という要件を満たせません。
4. 実測（元コード、MSVC）：24 件が表示され、`copy-copy-A=2`、`copy-copy-B=3`、`copy-` を 16 回重ねた `C` などが生成されました。異常終了はしませんでした。MSVC の `unordered_map` は内部がリスト構造で、実装上は再ハッシュ後もイテレータが壊れないためです。ASan とデバッグイテレータ（`/MTd /D_ITERATOR_DEBUG_LEVEL=2`）も何も報告しませんでした。ただし規格上は未定義動作で、出力内容も誤っています。別の標準ライブラリ実装では、クラッシュや無限ループになるおそれがあります。

**【修正済みC++17コード：全文】**

```cpp
#include <iostream>
#include <map>
#include <string>
#include <string_view>
#include <unordered_map>
#include <utility>
#include <vector>

constexpr std::string_view kCopyPrefix = "copy-";

static bool isCopyKey(const std::string& key) {
    return key.compare(0, kCopyPrefix.size(), kCopyPrefix) == 0;
}

// 元データ（"copy-" で始まらないキー）ごとに "copy-<key>" を追加する。
// 反復中のコンテナには挿入しない: まず複製を別のvectorに集め、反復が終わってから挿入する。
// さらに作業用コピーに挿入してから noexcept な swap で確定するので、途中で例外
// （bad_alloc など）が出ても counts は元のまま残る。
// 既に "copy-" で始まるキーは複製しないため、何度呼んでも "copy-copy-" は生成されない。
void addCopies(std::unordered_map<std::string, int>& counts) {
    std::vector<std::pair<std::string, int>> pending;
    pending.reserve(counts.size());
    for (const auto& [key, value] : counts) {  // この反復中はcountsを変更しない
        if (!isCopyKey(key)) {
            pending.emplace_back(std::string(kCopyPrefix) + key, value);
        }
    }

    std::unordered_map<std::string, int> next = counts;
    next.reserve(next.size() + pending.size());
    for (auto& [key, value] : pending) {
        next.insert_or_assign(std::move(key), value);  // 元コードの operator[]= と同じ上書き意味論
    }
    counts.swap(next);
}

static std::map<std::string, int> sorted(const std::unordered_map<std::string, int>& m) {
    return std::map<std::string, int>(m.begin(), m.end());
}

int main() {
    std::unordered_map<std::string, int> counts{
        {"A", 2}, {"B", 3}, {"C", 5}
    };
    addCopies(counts);
    for (const auto& item : sorted(counts)) {  // キーの昇順で表示
        std::cout << item.first << '=' << item.second << '\n';
    }

    // ---- 追加検証 ----
    int failures = 0;
    auto check = [&](bool cond, const std::string& label) {
        std::cout << (cond ? "  PASS: " : "  FAIL: ") << label << '\n';
        if (!cond) ++failures;
    };
    std::cout << "[Tests]\n";
    const std::map<std::string, int> expected{{"A", 2}, {"B", 3}, {"C", 5},
                                              {"copy-A", 2}, {"copy-B", 3}, {"copy-C", 5}};
    check(sorted(counts) == expected, "exactly 6 entries A,B,C,copy-A,copy-B,copy-C");

    // 再実行しても増えない（copy-copy- を作らない）
    addCopies(counts);
    check(sorted(counts) == expected, "second call is idempotent (no copy-copy-)");

    // 空の入力
    std::unordered_map<std::string, int> empty;
    addCopies(empty);
    check(empty.empty(), "empty input stays empty");

    // 既に copy- キーを含む入力: 複製せず、元キーの値で copy-A を上書き
    std::unordered_map<std::string, int> mixed{{"A", 1}, {"copy-A", 99}, {"copy-X", 7}};
    addCopies(mixed);
    check(sorted(mixed) == std::map<std::string, int>{{"A", 1}, {"copy-A", 1}, {"copy-X", 7}},
          "pre-existing copy- keys are not duplicated");

    // 大量件数 + 再ハッシュを強制（max_load_factor を小さくする）
    std::unordered_map<std::string, int> big;
    big.max_load_factor(0.25f);
    constexpr int kN = 100000;
    for (int i = 0; i < kN; ++i) {
        big.emplace("K" + std::to_string(i), i);
    }
    const std::size_t bucketsBefore = big.bucket_count();
    addCopies(big);
    const std::size_t bucketsAfter = big.bucket_count();
    bool bigOk = big.size() == static_cast<std::size_t>(2 * kN);
    for (int i = 0; i < kN && bigOk; ++i) {
        const std::string k = "K" + std::to_string(i);
        bigOk = big.at(k) == i && big.at("copy-" + k) == i;
    }
    for (const auto& kv : big) {
        if (kv.first.compare(0, 10, "copy-copy-") == 0) {
            bigOk = false;
        }
    }
    std::cout << "  buckets before=" << bucketsBefore << " after=" << bucketsAfter << '\n';
    check(bigOk, "100000 originals -> 200000 entries, all copies correct");
    check(bucketsAfter > bucketsBefore, "rehash occurred while adding copies (bucket count grew)");

    std::cout << "Result: " << (failures == 0 ? "ALL PASS" : "FAILURES") << '\n';
    return failures == 0 ? 0 : 1;
}
```

**【修正内容と安全性の説明】**

- **2段階に分ける**：まず元のコンテナを読むだけで反復し、追加する `("copy-" + key, value)` を別の `std::vector` に集めます。反復が終わってから挿入するので、反復中にコンテナは変わらず、イテレータの無効化も反復対象の増加も起きません。

## Q06：複数フィールドの整合性とデータ競合

**難易度：高難度**

### クライアント要望

4スレッドが統計を同時更新し、監視スレッドが進捗を読み取ります。個々の値を単独で修正するだけでなく、countとtotalを常に一貫した組として観測できるようにしてください。

### 元コード（編集禁止）

```cpp
#include <atomic>
#include <iostream>
#include <thread>
#include <utility>
#include <vector>

struct Stats {
    int count = 0;
    int total = 0;
    void add() {
        ++count;
        ++total;
    }
    std::pair<int, int> snapshot() const {
        return {count, total};
    }
};

int main() {
    Stats stats;
    std::atomic<bool> done{false};
    std::atomic<bool> inconsistent{false};

    std::thread observer([&] {
        while (!done.load()) {
            auto snapshot = stats.snapshot();
            if (snapshot.first != snapshot.second) {
                inconsistent.store(true);
            }
        }
    });

    std::vector<std::thread> writers;
    for (int n = 0; n < 4; ++n) {
        writers.emplace_back([&] {
            for (int i = 0; i < 10000; ++i) {
                stats.add();
            }
        });
    }
    for (auto& t : writers) t.join();
    done.store(true);
    observer.join();
    auto result = stats.snapshot();
    std::cout << "Count=" << result.first
              << " Total=" << result.second
              << " Inconsistent=" << inconsistent.load() << '\n';
}
```

### 期待結果・合格条件

Count=40000 Total=40000 Inconsistent=0。監視中のスナップショットも常に整合している。

### 必須要件

- データ競合を解消し、値の対としての一貫性も保証する
- 書き込みと読み取りの両方を適切に同期させる
- 実行を繰り返して最終結果と監視結果を確認する
- 可能ならThreadSanitizerなどで競合の有無を確認する（不可なら未実施と記載）

### ★HERCULES回答欄 Q06

**【不具合の根本原因】**

1. **データ競合**：`count` と `total` は同期なしの `int` です。4つの書き込みスレッドが `++` を同時に実行し、監視スレッドも同期なしで読んでいます。これは規格上のデータ競合で、未定義動作です。`++` は「読み込み、加算、書き込み」の3段階に分かれるため、更新が失われます。
2. **組としての不整合**：仮に `count` と `total` をそれぞれ `std::atomic<int>` にしても、`add()` の2つの更新の間や `snapshot()` の2つの読み取りの間に、ほかのスレッドが入り込めます。そのため、`count` だけ進んで `total` はまだ、という**ずれた組**が観測されます。個々の値の修正だけでは要件を満たしません。
3. 実測（元コード）：`/Od` で `Count=26676 Total=26579 Inconsistent=1` と `Count=27988 Total=28022 Inconsistent=1`。`/O2` を5回実行すると `Count=38157 Total=38078 Inconsistent=1` が1回、`Count=40000 Total=40000 Inconsistent=1` が4回でした。**最終値が偶然 40000 になった回でも、監視中には不整合が観測されています**。

```cpp
#include <atomic>
#include <iostream>
#include <mutex>
#include <thread>
#include <utility>
#include <vector>

// count と total をひとつの mutex で保護する。add は2つの値を同じ臨界区間で更新し、
// snapshot も同じ mutex を取ってから読むので、観測される組は常に整合している。
class Stats {
    mutable std::mutex mu_;  // const な snapshot() からもロックできるよう mutable
    int count_ = 0;
    int total_ = 0;
public:
    void add() {
        std::lock_guard<std::mutex> lock(mu_);
        ++count_;
        ++total_;
    }
    std::pair<int, int> snapshot() const {
        std::lock_guard<std::mutex> lock(mu_);
        return {count_, total_};
    }
};

struct RunResult {
    std::pair<int, int> final;
    bool inconsistent;
    bool nonMonotonic;
    long long observations;
    long long inFlightObservations;  // 書き込み途中（0 < count < 40000）を観測した回数
};

static RunResult runOnce() {
    Stats stats;
    std::atomic<bool> done{false};
    std::atomic<bool> inconsistent{false};
    std::atomic<bool> nonMonotonic{false};
    long long observations = 0;
    long long inFlight = 0;

    std::thread observer([&] {
        int lastCount = 0;
        // done を立てた後にも最低1回は観測するよう do-while にする
        do {
            const auto snapshot = stats.snapshot();
            ++observations;
            if (snapshot.first > 0 && snapshot.first < 40000) ++inFlight;
            if (snapshot.first != snapshot.second) inconsistent.store(true);
            if (snapshot.first < lastCount) nonMonotonic.store(true);
            lastCount = snapshot.first;
        } while (!done.load());
    });

    std::vector<std::thread> writers;
    for (int n = 0; n < 4; ++n) {
        writers.emplace_back([&] {
            for (int i = 0; i < 10000; ++i) {
                stats.add();
            }
        });
    }
    for (auto& t : writers) t.join();
    done.store(true);
    observer.join();  // join により observations / inFlight の読み取りは同期済み
    return {stats.snapshot(), inconsistent.load(), nonMonotonic.load(), observations, inFlight};
}

int main() {
    const RunResult first = runOnce();
    std::cout << "Count=" << first.final.first
              << " Total=" << first.final.second
              << " Inconsistent=" << first.inconsistent << '\n';

    // 繰り返し実行して最終値と監視結果を確認する
    constexpr int kRuns = 200;
    int bad = 0;
    long long totalObs = 0;
    long long totalInFlight = 0;
    for (int r = 0; r < kRuns; ++r) {
        const RunResult res = runOnce();
        totalObs += res.observations;
        totalInFlight += res.inFlightObservations;
        if (res.final.first != 40000 || res.final.second != 40000 || res.inconsistent ||
            res.nonMonotonic) {
            ++bad;
            std::cout << "  FAIL run " << r << ": Count=" << res.final.first
                      << " Total=" << res.final.second << " Inconsistent=" << res.inconsistent
                      << " NonMonotonic=" << res.nonMonotonic << '\n';
        }
    }
    std::cout << "Repeat: runs=" << kRuns << " bad=" << bad
              << " snapshots=" << totalObs << " in-flight snapshots=" << totalInFlight << '\n';
    std::cout << "Result: " << (bad == 0 ? "ALL PASS" : "FAILURES") << '\n';
    return bad == 0 ? 0 : 1;
}
```

**【修正内容と安全性の説明】**

- `Stats` に `mutable std::mutex mu_` を1つ持たせ、`add()` は2つの値の更新を、`snapshot()` は2つの値の読み取りを、どちらも同じ `std::lock_guard` の臨界区間で行います。書き込みと読み取りが同じ mutex で同期されるため、データ競合はなく、`snapshot()` が返す組はいつも「ある `add()` 全体の前か後」の状態です（線形化可能）。`mutable` は、`const` な `snapshot()` からロックできるようにするためです。
- `count_`／`total_` を private にして、ロックを通らないアクセスをできなくしました。

## Q07：condition_variableと安全なキュー終了

**難易度：高難度**

### クライアント要望

3つのワーカースレッドが共有キューから仕事を取り出します。待機からの誤った復帰、終了通知の不足、終了後の投入受付が問題です。キューの仕事をすべて処理してから全スレッドを停止させてください。

### 元コード（編集禁止）

```cpp
#include <atomic>
#include <condition_variable>
#include <iostream>
#include <mutex>
#include <queue>
#include <thread>
#include <vector>

class WorkQueue {
    std::queue<int> jobs;
    std::mutex mu;
    std::condition_variable cv;
    bool closed = false;
public:
    void push(int value) {
        std::lock_guard<std::mutex> lock(mu);
        jobs.push(value);
        cv.notify_one();
    }
    bool pop(int& value) {
        std::unique_lock<std::mutex> lock(mu);
        if (jobs.empty()) cv.wait(lock);
        if (jobs.empty()) return false;
        value = jobs.front();
        jobs.pop();
        return true;
    }
    void close() {
        std::lock_guard<std::mutex> lock(mu);
        closed = true;
        cv.notify_one();
    }
};

int main() {
    WorkQueue queue;
    std::atomic<int> sum{0};
    std::atomic<int> processed{0};
    std::vector<std::thread> workers;
    for (int i = 0; i < 3; ++i) {
        workers.emplace_back([&] {
            int value;
            while (queue.pop(value)) {
                sum.fetch_add(value);
                processed.fetch_add(1);
            }
        });
    }
    for (int i = 1; i <= 100; ++i) queue.push(i);
    queue.close();
    for (auto& t : workers) t.join();
    std::cout << "Processed=" << processed
              << " Sum=" << sum << '\n';
}
```

### 期待結果・合格条件

Processed=100 Sum=5050。全ワーカーが終了し、ハングしない。close後の新しいpushは拒否される。

### 必須要件

- 条件変数の待機条件を正しく扱う
- 処理待ちのキューを空にしてから全ワーカーを終了する
- closeを複数回呼んでも破綻しない
- 終了後のpush拒否、空キュー終了、複数回実行を検証する
- ハングの可能性がある元コードは外部タイムアウト付きで実行する

### ★HERCULES回答欄 Q07

**【不具合の根本原因】**

1. **終了条件を待機条件に含めていない**：`pop` の `if (jobs.empty()) cv.wait(lock);` は `closed` を一切見ていません。仕事を処理し終えて戻ってきたワーカーは、キューが空なら無条件に `wait` に入ります。`close()` がすでに実行され通知が済んでいれば、もう誰も通知しないので**永久に待ち続けます**。これがハングの主な原因です。
2. **終了通知の不足**：`close()` は `notify_one()` なので、待機中のワーカーが複数いても1つしか起きません。残りは起こされず、`join` が戻りません。
3. **述語なしの wait**：`wait` は通知がなくても復帰することがあります（spurious wakeup）。復帰後に `jobs.empty()` なら、閉じられていなくても `false` を返し、ワーカーが早く終了してしまいます。逆に、`if` で一度しか確かめないので、条件が成り立つまで待つという保証もありません。
4. **close 後の push を受け付ける**：`push` は `closed` を確かめないので、close 後の仕事もキューに入ります。ワーカーが終了していれば処理されずに消えます。
5. 実測（元コード）：外部タイムアウト付きで実行し、`/Od /Zi` 版は 10 秒、`/Od`・`/O2` 版は各 5 回とも 5 秒でタイムアウトして強制終了（合計 11 回すべてハング）。標準出力は何も出ませんでした。

```cpp
#include <atomic>
#include <condition_variable>
#include <iostream>
#include <mutex>
#include <queue>
#include <string>
#include <thread>
#include <vector>

class WorkQueue {
    std::queue<int> jobs;
    std::mutex mu;
    std::condition_variable cv;
    bool closed = false;
public:
    // close 後は受け付けず false を返す（投入した仕事が黙って消えることはない）。
    [[nodiscard]] bool push(int value) {
        {
            std::lock_guard<std::mutex> lock(mu);
            if (closed) return false;
            jobs.push(value);
        }
        cv.notify_one();
        return true;
    }

    // 仕事があれば取り出して true。close 済みかつ空になったら false（ワーカー終了）。
    // 述語付き wait なので、偽の復帰（spurious wakeup）や通知の取りこぼしがあっても
    // 条件が成り立つまで待ち続ける。close 後もキューに残った仕事は先に処理される。
    bool pop(int& value) {
        std::unique_lock<std::mutex> lock(mu);
        cv.wait(lock, [this] { return closed || !jobs.empty(); });
        if (jobs.empty()) return false;  // closed && empty
        value = jobs.front();
        jobs.pop();
        return true;
    }

    // 冪等。待機中の全ワーカーを起こす。
    void close() {
        {
            std::lock_guard<std::mutex> lock(mu);
            if (closed) return;
            closed = true;
        }
        cv.notify_all();
    }
};

struct Outcome {
    int processed;
    int sum;
};

// workerCount 本のワーカーで jobs を処理する。producers 本のスレッドが 1..perProducer を投入する。
static Outcome runScenario(int workerCount, int producers, int perProducer, bool closeTwice,
                           bool& rejectedAfterClose) {
    WorkQueue queue;
    std::atomic<int> sum{0};
    std::atomic<int> processed{0};
    std::vector<std::thread> workers;
    for (int i = 0; i < workerCount; ++i) {
        workers.emplace_back([&] {
            int value;
            while (queue.pop(value)) {
                sum.fetch_add(value);
                processed.fetch_add(1);
            }
        });
    }
    std::vector<std::thread> producerThreads;
    std::atomic<int> refused{0};
    for (int p = 0; p < producers; ++p) {
        producerThreads.emplace_back([&] {
            for (int i = 1; i <= perProducer; ++i) {
                if (!queue.push(i)) refused.fetch_add(1);
            }
        });
    }
    for (auto& t : producerThreads) t.join();
    queue.close();
    if (closeTwice) queue.close();
    rejectedAfterClose = !queue.push(999999) && refused.load() == 0;
    for (auto& t : workers) t.join();
    return {processed.load(), sum.load()};
}
```

**【修正内容と安全性の説明】**

- `pop` は述語付きの `cv.wait(lock, [this]{ return closed || !jobs.empty(); })` にしました。spurious wakeup では待ち直し、通知より前に条件が成り立っていれば待たずに進みます。復帰後にキューが空なら「閉じられていて空」なので `false` を返し、ワーカーを終了させます。空でなければ、閉じられた後でも先に残りの仕事を取り出すので、キューを空にしてから全ワーカーが終了します。
- `close()` はロック内で `closed` を立て、すでに閉じられていれば何もしません（冪等）。ロックを外してから `notify_all()` で待機中のワーカーを全部起こします。
- `push()` はロック内で `closed` を確かめ、閉じられていれば `false` を返して拒否します（`[[nodiscard]]`）。受け付けた仕事は必ず処理されます。
- `closed` とキューへのアクセスはすべて同じ `mu` の下で行います。通知はロックを外してから行い、起こされたスレッドがすぐにまたロック待ちになるのを避けます。

## Q08：Rule of Fiveとリソースの二重解放

**難易度：高難度**

### クライアント要望

動的配列を所有するBufferクラスをコピー・代入・ムーブして利用します。現状はコピーで所有権が共有され、解放済みメモリへのアクセスや二重解放が起こります。例外安全性と自己代入も含めて修正してください。

### 元コード（編集禁止）

```cpp
#include <cstddef>
#include <iostream>
#include <utility>

class Buffer {
    char* data_;
    std::size_t size_;
public:
    explicit Buffer(std::size_t n)
        : data_(new char[n]()), size_(n) {}

    ~Buffer() { delete[] data_; }

    char& at(std::size_t i) { return data_[i]; }
    const char& at(std::size_t i) const { return data_[i]; }
    std::size_t size() const { return size_; }
};

int main() {
    Buffer a(4);
    a.at(0) = 'A';
    Buffer b = a;
    b.at(1) = 'B';
    Buffer c = std::move(b);
    std::cout << "A0=" << a.at(0)
              << " A1=" << int(a.at(1))
              << " C1=" << c.at(1) << '\n';
}
```

### 期待結果・合格条件

A0=A A1=0 C1=B。独立したコピー、所有権の移動、正常な破棄を保証する。

### 必須要件

- 所有リソースのコピー・ムーブ・破棄の設計を正しくする
- 自己コピー代入、自己ムーブ代入でも破綻しない
- 境界外のatアクセスを安全に拒否する
- コピーとムーブ後に二重解放、メモリリーク、解放済み参照がないことを検証する
- 例外発生時も所有権と元データの整合性を維持する

### ★HERCULES回答欄 Q08

**【不具合の根本原因】**

1. **浅いコピー**：`Buffer` はデストラクタで `delete[]` していますが、コピーコンストラクタとコピー代入を定義していません。暗黙の定義はメンバーごとのコピーなので、`Buffer b = a;` で `data_` のポインタだけが複製され、`a` と `b` が同じ配列を共有します。`b.at(1) = 'B'` は `a` の内容も書き換えます。
2. **ムーブが実はコピー**：ユーザー定義のデストラクタがあるため、ムーブコンストラクタは暗黙に宣言されません。`Buffer c = std::move(b);` は暗黙のコピーコンストラクタで処理され、`c` も同じ配列を共有します。
3. **二重解放**：スコープの終わりに `c`、`b`、`a` のデストラクタが同じポインタを `delete[]` します（3回解放される）。2回目以降は未定義動作です。
4. **範囲検査なし**：`at` は添字を検査せず、範囲外を読み書きします。
5. 実測（元コード）：通常ビルドは終了コード `0xC0000374`（STATUS_HEAP_CORRUPTION）で異常終了し、標準出力は何も得られませんでした（パイプ出力時のバッファが破棄されたため）。ASan ビルドでは `ERROR: AddressSanitizer: attempting double-free` を `Buffer::~Buffer` で検出しました（最初の解放も `~Buffer`、確保は `Buffer::Buffer`）。

**【修正済みC++17コード：全文】**

```cpp
#include <algorithm>
#include <cstddef>
#include <iostream>
#include <new>
#include <stdexcept>
#include <string>
#include <utility>

// 検証用の確保カウンタと障害注入（Buffer の確保・解放はすべてここを通る）
namespace alloc_track {
inline long long live = 0;            // 未解放の配列数
inline long long allocations = 0;
inline long long deallocations = 0;
inline bool failNext = false;         // true なら次の確保で std::bad_alloc を投げる

inline char* allocate(std::size_t n) {
    if (n == 0) return nullptr;
    if (failNext) {
        failNext = false;
        throw std::bad_alloc();
    }
    char* p = new char[n]();  // 0 初期化
    ++live;
    ++allocations;
    return p;
}
inline void release(char* p) noexcept {
    if (p == nullptr) return;
    delete[] p;
    --live;
    ++deallocations;
}
}  // namespace alloc_track

// 動的配列を単独所有するクラス（Rule of Five）。
// 不変条件: (data_ == nullptr) == (size_ == 0)。ムーブ元は size()==0 の有効な空状態になる。
class Buffer {
    char* data_ = nullptr;
    std::size_t size_ = 0;
public:
    explicit Buffer(std::size_t n)
        : data_(alloc_track::allocate(n)), size_(n) {}

    ~Buffer() { alloc_track::release(data_); }

    // コピー: 新しい配列を確保して内容を複製（深いコピー）。確保失敗時は何も確保されない。
    Buffer(const Buffer& other)
        : data_(alloc_track::allocate(other.size_)), size_(other.size_) {
        std::copy_n(other.data_, size_, data_);
    }

    // ムーブ: 所有権を移し、ムーブ元を空にする。
    Buffer(Buffer&& other) noexcept
        : data_(std::exchange(other.data_, nullptr)),
          size_(std::exchange(other.size_, 0)) {}

    // コピー代入: copy-and-swap で強い例外安全保証。自己代入でも正しい。
    Buffer& operator=(const Buffer& other) {
        if (this != &other) {
            Buffer tmp(other);  // ここで例外が出ても *this は無変更
            swap(tmp);          // noexcept
        }                       // 古い配列は tmp と一緒に解放される
        return *this;
    }

    // ムーブ代入: 自己ムーブは何もしない。
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            alloc_track::release(data_);
            data_ = std::exchange(other.data_, nullptr);
            size_ = std::exchange(other.size_, 0);
        }
        return *this;
    }

    void swap(Buffer& other) noexcept {
        std::swap(data_, other.data_);
        std::swap(size_, other.size_);
    }
    friend void swap(Buffer& a, Buffer& b) noexcept { a.swap(b); }

    // 範囲外は std::out_of_range（ムーブ後の空バッファでも安全に拒否）
    char& at(std::size_t i) {
        if (i >= size_) throw std::out_of_range("Buffer::at index out of range");
        return data_[i];
    }
    const char& at(std::size_t i) const {
        if (i >= size_) throw std::out_of_range("Buffer::at index out of range");
        return data_[i];
    }
    std::size_t size() const noexcept { return size_; }
};

static int g_failures = 0;
static void check(bool cond, const std::string& label) {
    std::cout << (cond ? "  PASS: " : "  FAIL: ") << label << '\n';
    if (!cond) ++g_failures;
}
template <class Fn>
static bool throwsOutOfRange(Fn fn) {
    try {
        fn();
    } catch (const std::out_of_range&) {
        return true;
    }
    return false;
}

int main() {
    {
        Buffer a(4);
        a.at(0) = 'A';
        Buffer b = a;
        b.at(1) = 'B';
        Buffer c = std::move(b);
        std::cout << "A0=" << a.at(0)
                  << " A1=" << int(a.at(1))
                  << " C1=" << c.at(1) << '\n';
    }

    std::cout << "[Tests]\n";
    check(alloc_track::live == 0 && alloc_track::allocations == 2 &&
              alloc_track::deallocations == 2,
          "original scenario: 2 allocations, 2 frees, no leak / no double free");

    {
        Buffer a(4);
        a.at(0) = 'A';
        Buffer b = a;  // 深いコピー
        b.at(0) = 'Z';
        check(a.at(0) == 'A' && b.at(0) == 'Z', "copy is independent");

        Buffer c = std::move(b);
        check(b.size() == 0 && c.size() == 4 && c.at(0) == 'Z', "move transfers ownership");
        check(throwsOutOfRange([&] { b.at(0); }), "moved-from buffer rejects at(0)");

        b = a;  // ムーブ元への再代入（再利用できる）
        check(b.size() == 4 && b.at(0) == 'A', "moved-from buffer can be reassigned");

        // 自己コピー代入 / 自己ムーブ代入
        Buffer& alias = a;
        a = alias;
        check(a.size() == 4 && a.at(0) == 'A', "self copy-assignment keeps data");
        a = std::move(alias);
        check(a.size() == 4 && a.at(0) == 'A', "self move-assignment keeps data");

        // 境界外アクセス
        check(throwsOutOfRange([&] { a.at(4); }), "at(size) throws out_of_range");
        check(throwsOutOfRange([&] { a.at(static_cast<std::size_t>(-1)); }),
              "at(SIZE_MAX) throws out_of_range");
        const Buffer& ca = a;
        check(throwsOutOfRange([&] { ca.at(4); }), "const at(size) throws out_of_range");
        check(ca.at(3) == 0, "last valid index is readable");

        // サイズ0
        Buffer z(0);
        check(z.size() == 0 && throwsOutOfRange([&] { z.at(0); }), "zero-size buffer");

        // 異なるサイズ間の代入
        Buffer big(16);
        big.at(15) = 'Q';
        a = big;
        check(a.size() == 16 && a.at(15) == 'Q' && big.at(15) == 'Q', "copy-assign larger");
        a = Buffer(2);
        check(a.size() == 2, "move-assign smaller temporary");

        // 例外安全: コピー代入中の確保失敗 -> 代入先は元のまま、リークなし
        Buffer target(3);
        target.at(0) = 'T';
        const long long liveBefore = alloc_track::live;
        alloc_track::failNext = true;
        bool threw = false;
        try {
            target = big;
        } catch (const std::bad_alloc&) {
            threw = true;
        }
        check(threw && target.size() == 3 && target.at(0) == 'T' && big.size() == 16 &&
                  alloc_track::live == liveBefore,
              "bad_alloc during copy-assign: target and source unchanged, no leak");

        // 例外安全: コピー構築中の確保失敗 -> リークなし
        alloc_track::failNext = true;
        threw = false;
        try {
            Buffer copy(big);
        } catch (const std::bad_alloc&) {
            threw = true;
        }
        check(threw && alloc_track::live == liveBefore, "bad_alloc during copy-construct: no leak");

        // swap
        swap(target, big);
        check(target.size() == 16 && big.size() == 3 && big.at(0) == 'T', "swap exchanges");
    }
    check(alloc_track::live == 0 && alloc_track::allocations == alloc_track::deallocations,
          "all buffers released exactly once (allocations=" +
              std::to_string(alloc_track::allocations) +
              ", deallocations=" + std::to_string(alloc_track::deallocations) + ")");

    std::cout << "Result: " << (g_failures == 0 ? "ALL PASS" : "FAILURES") << '\n';
    return g_failures == 0 ? 0 : 1;
}
```

**【修正内容と安全性の説明】**

- **Rule of Five**：深いコピーを行うコピーコンストラクタ、`noexcept` のムーブコンストラクタ、copy-and-swap によるコピー代入、`noexcept` のムーブ代入、デストラクタ、`noexcept` の `swap` を定義しました。
- **不変条件**：`(data_ == nullptr) == (size_ == 0)`。ムーブ元は `std::exchange` で `nullptr`／0 にし、「有効な空状態」にします（`size()==0`、`at` は例外、再代入して再利用できる）。
- **例外安全**：コピーコンストラクタは確保が成功してからメンバーを初期化するので、確保に失敗しても何も漏れません。コピー代入は、一時オブジェクトへのコピー（失敗しうる）と `noexcept` な `swap` を組み合わせた強い保証です。失敗しても代入先は元のままで、古い配列は一時オブジェクトと一緒に一度だけ解放されます。
- **自己代入**：コピー代入とムーブ代入の両方で `this != &other` を確かめ、何もしないようにしました（copy-and-swap だけでも自己コピー代入は正しく動きますが、無駄なコピーを避けます）。
- **範囲検査**：`at` は `i >= size_` なら `std::out_of_range` を投げます（`const` 版も同じ）。
- 検証のため、確保と解放を `alloc_track` で数え、次の確保を `std::bad_alloc` で失敗させる障害注入も用意しました。本番でこの仕組みが不要なら、`allocate` を `new char[n]()` に、`release` を `delete[]` に戻すだけです。`std::unique_ptr<char[]>` で持つ設計（Rule of Zero に近い）にもできますが、課題の趣旨に合わせて Rule of Five で実装しました。

## Q09：std::futureでの例外回収と部分成功

**難易度：高難度**

### クライアント要望

非同期計算の一部が例外を投げます。1つの失敗で集計全体を中止せず、成功値を正しく合計し、失敗件数を報告してください。すべての非同期処理の完了・例外回収が必要です。

### 元コード（編集禁止）

```cpp
#include <future>
#include <iostream>
#include <stdexcept>
#include <vector>

int main() {
    std::vector<std::future<int>> futures;
    for (int i = 1; i <= 5; ++i) {
        futures.push_back(std::async(std::launch::async, [i] {
            if (i == 3) throw std::runtime_error("job 3 failed");
            return i * i;
        }));
    }
    int sum = 0;
    for (auto& future : futures) {
        sum += future.get();
    }
    std::cout << "Sum=" << sum << '\n';
}
```

### 期待結果・合格条件

Success=4 Failed=1 Sum=46。失敗したジョブの原因が報告され、残りのfutureもすべて取得する。

### 必須要件

- future.getによる例外の伝播を正しく処理する
- 失敗しても残りのfutureを処理する
- ジョブごとの成功・失敗を判定する
- 全件成功、全件失敗、部分失敗のケースを検証する

### ★HERCULES回答欄 Q09

**【不具合の根本原因】**

1. `std::async` で実行した関数が投げた例外は、共有状態に保存され、`future.get()` を呼んだときに**呼び出し側で再送出**されます。元コードの集計ループには `try/catch` がないため、ジョブ 3 の `get()` が `std::runtime_error` を再送出すると、例外は `main` の外へ伝わって `std::terminate` から `abort()` が呼ばれます。
2. その結果、ジョブ 4・5 の `get()` は呼ばれず、成功値は集計されず、失敗件数も理由も報告されません。異常終了なので、残りのジョブの結果も例外も回収されません。
3. 実測（元コード）：終了コード `0xC0000409`（`abort()`）で異常終了し、`Sum=` は表示されませんでした。

**【修正済みC++17コード：全文】**

```cpp
#include <exception>
#include <functional>
#include <future>
#include <iostream>
#include <stdexcept>
#include <string>
#include <system_error>
#include <vector>

struct JobOutcome {
    int id = 0;
    bool ok = false;
    int value = 0;
    std::string error;
};

struct Summary {
    int succeeded = 0;
    int failed = 0;
    long long sum = 0;  // 成功値の合計（int の和のオーバーフローを避ける）
    std::vector<JobOutcome> outcomes;
};

// ジョブ 1..count を std::async で並行実行し、すべての future を個別に回収する。
// 1つの get() が例外を投げても、残りの future の get() は必ず実行される。
Summary runAll(int count, const std::function<int(int)>& job) {
    struct Pending {
        int id;
        std::future<int> future;
        std::string launchError;  // スレッドを起動できなかった場合
    };
    std::vector<Pending> pending;
    pending.reserve(static_cast<std::size_t>(count > 0 ? count : 0));
    for (int i = 1; i <= count; ++i) {
        try {
            pending.push_back({i, std::async(std::launch::async, job, i), {}});
        } catch (const std::system_error& e) {
            pending.push_back({i, std::future<int>{}, std::string("launch failed: ") + e.what()});
        }
    }

    Summary s;
    for (auto& p : pending) {
        JobOutcome o;
        o.id = p.id;
        if (!p.future.valid()) {
            o.error = p.launchError;
        } else {
            try {
                o.value = p.future.get();  // ジョブ内の例外はここで再送出される
                o.ok = true;
            } catch (const std::exception& e) {
                o.error = e.what();
            } catch (...) {
                o.error = "unknown (non-std) exception";
            }
        }
        if (o.ok) {
            ++s.succeeded;
            s.sum += o.value;
        } else {
            ++s.failed;
        }
        s.outcomes.push_back(std::move(o));
    }
    return s;
}

static void print(const Summary& s) {
    std::cout << "Success=" << s.succeeded << " Failed=" << s.failed << " Sum=" << s.sum << '\n';
    for (const auto& o : s.outcomes) {
        if (!o.ok) std::cout << "  job " << o.id << " failed: " << o.error << '\n';
```

### 元コード（編集禁止）

```cpp
#include <condition_variable>
#include <functional>
#include <future>
#include <iostream>
#include <memory>
#include <mutex>
#include <queue>
#include <stdexcept>
#include <thread>
#include <type_traits>
#include <utility>
#include <vector>

class ThreadPool {
    std::vector<std::thread> workers_;
    std::queue<std::function<void()>> jobs_;
    std::mutex mu_;
    std::condition_variable cv_;
    bool stopped_ = false;

    void worker() {
        while (true) {
            std::unique_lock<std::mutex> lock(mu_);
            cv_.wait(lock);
            if (stopped_) return;
            if (jobs_.empty()) continue;
            auto job = std::move(jobs_.front());
            jobs_.pop();
            lock.unlock();
            job();
        }
    }

public:
    explicit ThreadPool(int count) {
        for (int i = 0; i < count; ++i) {
            workers_.emplace_back([this] { worker(); });
        }
    }

    template<class F>
    auto submit(F task) -> std::future<std::invoke_result_t<F>> {
        using R = std::invoke_result_t<F>;
        auto packaged =
            std::make_shared<std::packaged_task<R()>>(std::move(task));
        auto future = packaged->get_future();
        {
            std::lock_guard<std::mutex> lock(mu_);
            jobs_.push([packaged] { (*packaged)(); });
        }
        cv_.notify_one();
        return future;
    }

    void stop() {
        {
            std::lock_guard<std::mutex> lock(mu_);
            stopped_ = true;
        }
        cv_.notify_one();
        for (auto& t : workers_) {
            if (t.joinable()) t.join();
        }
    }

    ~ThreadPool() { stop(); }
};

int main() {
    ThreadPool pool(3);
    std::vector<std::future<int>> results;
    for (int i = 1; i <= 20; ++i) {
        results.push_back(pool.submit([i] {
            if (i == 13) throw std::runtime_error("job 13 failed");
            return i * i;
        }));
    }
    pool.stop();
    int succeeded = 0, failed = 0, sum = 0;
    for (auto& f : results) {
        try {
            sum += f.get();
            ++succeeded;
        } catch (const std::exception&) {
            ++failed;
        }
    }
    std::cout << "Success=" << succeeded
              << " Failed=" << failed
              << " Sum=" << sum << '\n';
    try {
        auto future = pool.submit([] { return 1; });
        std::cout << "Rejected=no\n";
    } catch (const std::exception&) {
        std::cout << "Rejected=yes\n";
    }
}
```

- ハングする元コードは外部タイムアウト付きで検証する

### ★HERCULES回答欄 Q10

**【不具合の根本原因】**

1. **待機条件の誤り**：`worker()` はループの先頭で、キューの状態を見ずに無条件に `cv_.wait(lock)` します。ワーカーが待機に入る前に `submit` が `notify_one` した通知は失われ、キューに仕事があっても眠り続けます。1回の通知で1件しか処理せず、処理後はまた無条件に待つので、残りの仕事は止まったままです。spurious wakeup で復帰した場合も、`jobs_.empty()` なら `continue` するだけで、待機条件として正しく定義されていません。
2. **停止時に保留中のタスクを捨てる**：`if (stopped_) return;` がキューを確かめる前にあるため、受け付け済みで未実行のタスクを捨てて終了します。捨てられたタスクの `packaged_task` は、最後にプールと一緒に破棄されます。その future の `get()` は結果を受け取れず、規格上 `std::future_error`（`broken_promise`）になります（元コードは先にハングするため、この挙動は実測していません）。
3. **停止通知の不足によるハング**：`stop()` は `notify_one()` なので、起きるワーカーは1つだけです。ほかのワーカーは `wait` のままで、`join` が永久に戻りません。
4. **停止後の投入を受け付ける**：`submit` は `stopped_` を確かめないので、停止後もタスクを受け付けます（`Rejected=no`）。そのタスクは実行されず、future は完了しません。
5. **stop の並行呼び出し**：複数のスレッドから `stop()` を同時に呼ぶと、同じ `std::thread` に `joinable()`／`join()` を同時に行うことになり、データ競合が起きます。
6. 実測（元コード）：外部タイムアウト付きで実行し、`/Od /Zi` 版は 10 秒、`/Od`・`/O2` 版は各 5 回とも 5 秒でタイムアウトして強制終了（合計 11 回すべてハング）。標準出力は何も出ませんでした。

```cpp
#include <atomic>
#include <chrono>
#include <condition_variable>
#include <functional>
#include <future>
#include <iostream>
#include <memory>
#include <mutex>
#include <queue>
#include <stdexcept>
#include <string>
#include <thread>
#include <type_traits>
#include <utility>
#include <vector>

class ThreadPool {
    std::vector<std::thread> workers_;
    std::queue<std::function<void()>> jobs_;
    std::mutex mu_;
    std::condition_variable cv_;
    bool stopped_ = false;
    std::mutex joinMu_;  // 複数スレッドから stop() が同時に呼ばれても join を直列化する

    void worker() {
        while (true) {
            std::function<void()> job;
            {
                std::unique_lock<std::mutex> lock(mu_);
                // 述語付き wait: 偽の復帰でも条件が成り立つまで待つ。通知前に条件が
                // 成立していれば待たずに進むので、通知の取りこぼしでハングしない。
                cv_.wait(lock, [this] { return stopped_ || !jobs_.empty(); });
                if (jobs_.empty()) return;  // 停止済みかつ受理済みタスクをすべて処理した
                job = std::move(jobs_.front());
                jobs_.pop();
            }
            job();  // ロック外で実行。タスクの例外は packaged_task が future に格納する
        }
    }

public:
    explicit ThreadPool(int count) {
        if (count <= 0) {
            throw std::invalid_argument("ThreadPool: count must be positive");
        }
        workers_.reserve(static_cast<std::size_t>(count));
        try {
            for (int i = 0; i < count; ++i) {
                workers_.emplace_back([this] { worker(); });
            }
        } catch (...) {
            stop();  // 起動済みのスレッドを止めて join してから例外を伝える
            throw;
        }
    }

    ThreadPool(const ThreadPool&) = delete;
    ThreadPool& operator=(const ThreadPool&) = delete;

    template<class F>
    auto submit(F task) -> std::future<std::invoke_result_t<F>> {
        using R = std::invoke_result_t<F>;
        auto packaged =
            std::make_shared<std::packaged_task<R()>>(std::move(task));
        auto future = packaged->get_future();
        {
            std::lock_guard<std::mutex> lock(mu_);
            if (stopped_) {
                throw std::runtime_error("ThreadPool: submit after stop");
            }
            jobs_.push([packaged] { (*packaged)(); });
        }
        cv_.notify_one();
        return future;
    }

    // 冪等。新規投入を止め、受理済みのタスクをすべて実行させてから全スレッドを join する。
    void stop() {
        {
            std::lock_guard<std::mutex> lock(mu_);
            stopped_ = true;
        }
        cv_.notify_all();  // 待機中の全ワーカーを起こす（notify_one では1本しか起きない）
        std::lock_guard<std::mutex> joinLock(joinMu_);  // mu_ は保持しない（ワーカーが進めるように）
        const auto self = std::this_thread::get_id();
        for (auto& t : workers_) {
            // タスク内から stop() が呼ばれた場合、自分自身は join できないので飛ばす
            // （そのスレッドはキューが空になると自分で終了し、後の stop()/デストラクタで join される）
            if (t.joinable() && t.get_id() != self) t.join();
        }
    }

    ~ThreadPool() { stop(); }
};

static int g_failures = 0;
static void check(bool cond, const std::string& label) {
    std::cout << (cond ? "  PASS: " : "  FAIL: ") << label << '\n';

}

struct MainResult {
```

**【修正内容と安全性の説明】**

- **公開 API は維持**：`explicit ThreadPool(int)`、`template<class F> auto submit(F) -> std::future<std::invoke_result_t<F>>`、`void stop()`、`~ThreadPool()` のシグネチャは元のままです（コピーは `delete` で明示的に禁止）。元の `main` と同じ処理がそのまま動きます。
- **待機条件**：`cv_.wait(lock, [this]{ return stopped_ || !jobs_.empty(); })`。復帰後、キューが空なら「停止済みで処理し終えた」ので終了し、空でなければ停止後でも取り出して実行します。タスクはロックの外で実行します。
- **stop**：ロック内で `stopped_ = true`（何度呼んでも同じ）→ ロックの外で `notify_all()` → `joinMu_` で直列化して、全スレッドを `join` します。`mu_` を持ったまま `join` しないので、ワーカーは残りのタスクを最後まで処理できます。並行して呼ばれた `stop()` は `joinMu_` で順番に処理され、`joinable()` で二重の join も防ぎます。タスクの中から `stop()` が呼ばれた場合は自分自身を join しないので、デッドロックしません。そのスレッドはキューが空になると自分で終了し、後の `stop()` かデストラクタで join されます。
- **投入拒否**：`submit` はロック内で `stopped_` を確かめ、停止後なら `std::runtime_error` をすぐに投げます。チェックとキューへの追加を同じ臨界区間で行うので、stop と競合しても「受け付けたのに実行されない」タスクは出ません。
- **例外の伝達**：タスクは `std::packaged_task` で包むので、タスクが投げた例外は future に保存され、`get()` で呼び出し側に再送出されます。ワーカースレッドは止まりません。
- **コンストラクタ**：`count <= 0` は `std::invalid_argument` で拒否します（0 にするとタスクが永久に実行されないため）。スレッドの作成が途中で失敗した場合は、作成済みのスレッドを `stop()` で止めてから例外を伝えます。
- 制約：デストラクタはプールのワーカースレッド自身から呼ばないことを前提にしています（タスクがプール自体を所有して破棄するような使い方はしない）。
