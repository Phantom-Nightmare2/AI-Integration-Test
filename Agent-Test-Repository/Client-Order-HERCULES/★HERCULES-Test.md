## 評価対象

- プログラミング能力

## 基本ルール

1. クライアントオーダーに従って作業すること。
2. 不明な内容は自律的に調査すること。
3. 問題ごとに原因・修正内容・検証結果を報告すること。
4. GitHubへのコミット・プッシュは明示的な許可がある場合のみ行うこと。

### ★HERCULESへのクライアントオーダー（Python）

1. **Q01〜Q10を順番に解く。** 各問の要求仕様・必須確認ケースを読み、元コードのエラー／バグ／仕様不一致を特定する。不明点は自律的に調査する。
2. **元の問題は変更禁止。** 「要求仕様」「必須確認ケース」「問題コード」を改変・削除せず、各問の「★HERCULESの回答」欄だけに記入する。こちらで問題を修正して難易度を下げることも禁止。
3. **各問に必須の回答：** ①原因と影響の説明、②仕様を満たす修正版のPythonコード全文（修正箇所に `#` コメント）、③検証手順・期待結果・実測結果。原因の説明だけ、差分だけ、未完成のコードだけでは提出不十分。
4. **自律検証：** 各問を独立した一時プログラムで実行し、正常系だけでなく指定された異常系・境界値・例外処理も確認する。元の不具合を再現可能なら再現し、修正版で解消したことを示す。
5. **安全性：** 実際のユーザーデータを使わず、SQLiteはテストDB、ファイル操作は一時ディレクトリ内で実施する。認証情報やAPIキーを取得・公開しない。検証用ファイルはリポジトリへ追加しない。
6. **結果の正確性：** 実行した検証と未実行の検証を区別し、未実行ならその理由・再現手順・予想結果を明記する。未確認の結果を実測・成功と偽らない。
7. **提出範囲：** このPython問題集の指定回答欄以外は編集しない。C#・C++の問題、過去の回答、README、LICENSE、AIエージェント設定に手を加えない。GitHubへのpushは所有者が明示的に許可した場合のみ行う。
8. **終了報告：** 回答済み問題数、実行・未実行の検証数、ローカルのコミットSHA（作成した場合）、pushの有無をクライアントへ報告する。★HERCULESによる自己採点や自己合格判定は禁止。

**採点基準：** 各問10点＝原因分析2点／仕様を満たす修正版コード6点／検証の方法と結果2点。採点・最終判定はクライアント側が行う。
